# MINDCRAFT — NEW MASTER BLUEPRINT
## Advanced Embodied-ML Product + Minecraft-Style Full-Screen Game
### Based on the current uploaded repository + revised product direction
### Date: 27 August 2026
### Status: Architecture / implementation master specification

======================================================================
0. PURPOSE OF THIS DOCUMENT
======================================================================

This document replaces the earlier "AI game" direction with a clearer
product architecture.

The project is NOT primarily a Minecraft clone.

The project is an ADVANCED ML PRODUCT presented through a polished,
Minecraft-inspired voxel world.

The core objective is:

    Build an autonomous embodied-AI system that is trained OFFLINE by
    the builder, evaluated scientifically, versioned, and then delivered
    to ordinary users as a finished trained AI experience.

The USER DOES NOT TRAIN THE MODEL.

The user receives:
    - a finished voxel game/world
    - trained autonomous AI entities
    - quests/challenges
    - AI-driven world behavior
    - optional explanations of AI behavior
    - a polished game interface

The BUILDER/ADMIN owns:
    - training
    - experiments
    - curriculum
    - evaluation
    - model versions
    - telemetry analysis
    - release gates
    - deployment
    - rollback
    - future retraining

The project should therefore be understood as:

    "An embodied-AI laboratory disguised as a polished voxel game."

----------------------------------------------------------------------
WHY THIS DIRECTION
----------------------------------------------------------------------

The uploaded repository already contains substantial ML and product
infrastructure:

    - Python/PyTorch reinforcement-learning training
    - custom voxel environments
    - PPO training scripts
    - multiple environment variants
    - evaluation and robustness scripts
    - PyTorch checkpoints
    - ONNX model artifacts
    - Next.js + TypeScript
    - Three.js voxel visualization
    - browser-side ONNX inference code
    - Prisma/PostgreSQL schema
    - authentication API routes
    - model APIs
    - telemetry APIs
    - challenge APIs
    - admin publish/rollback routes
    - experiments/evaluation pages
    - Unity C# bridge/inference files

The repository is therefore NOT starting from zero.

The major problem is not "we need more technologies."

The major problem is that the existing pieces need to become one coherent,
real product with a strong separation between:

    1. TRAINING
    2. PRODUCTION INFERENCE
    3. PRODUCT / DATABASE / USERS
    4. BUILDER MLOps CONTROL

The uploaded project audit already identifies mocked/hard-coded areas,
incomplete persistent telemetry, incomplete authentication/RBAC,
incomplete model-registry integration, and incomplete production
connections.

Therefore this blueprint focuses on CONNECTING and REFINING the existing
system instead of throwing it away.

1. FINAL PRODUCT DEFINITION
======================================================================

PROJECT NAME:
    MINDCRAFT

PRODUCT POSITIONING:
    Adaptive Embodied AI in a Persistent Voxel World

ONE-SENTENCE DESCRIPTION:
    A browser-based voxel world where autonomous agents execute
    policies trained locally through reinforcement learning, while the

    The user does not open a "training dashboard" and train an AI.

2. THE MOST IMPORTANT ARCHITECTURAL RULE
======================================================================

NEVER make public users responsible for training the production model.

Users generate useful behavioral telemetry.

That telemetry can become INPUT to a future offline training dataset.

But:

    PUBLIC USER DATA
          |
          v
      VALIDATE
          |
          v
       FILTER
          |
          v
     AGGREGATE
          |
          v
   OFFLINE TRAINING DATA
          |
          v
       TRAIN
          |
          v
      EVALUATE
          |
          v
     RELEASE GATE
          |
          v
   PRODUCTION MODEL

NOT:

    USER ACTION
        ->
    LIVE WEIGHT UPDATE
        ->
    PRODUCTION AI

This prevents model poisoning, unpredictable behavior, and uncontrolled
production changes.

    TARGET

    SOCIAL

    [health,

======================================================================
18. PPO TRAINING LOOP
======================================================================

Official Unity ML-Agents documentation describes the core RL pattern as
an environment producing observations, an Agent selecting actions, and
rewards being used to learn a policy. ML-Agents supports PPO, curriculum
learning, environment parameter randomization, multiple concurrent
environments, and multi-agent scenarios.

Our conceptual loop:

              OBSERVATION
                   |
                   v
              POLICY NETWORK
                   |
                   v
                ACTION
                   |
                   v
              VOXEL WORLD
                   |
                   v
                REWARD
                   |
                   v
            NEXT OBSERVATION
                   |
                   v
               PPO UPDATE
                   |
                   +--------------------+
                                        |
                                        v
                                   repeat

Source basis:
Unity ML-Agents official training documentation.

======================================================================
19. REWARD ENGINEERING
======================================================================

Reward should encourage the objective, not merely movement.

Example:

    +0.1   useful progress
    +1     discovery
    +5     resource collected
    +10    objective completed
    +3     safe return
    -0.1   wasted step
    -1     unnecessary collision
    -5     severe failure
    -10    death/episode failure

BUT:

Do not freeze these values forever.

Reward design is part of experimentation.

We need to detect:

    reward hacking
    looping behavior
    exploiting edge cases
    unsafe shortcuts

A real experiment:

    Reward v1
        ->
    observed failure
        ->
    diagnose
        ->
    Reward v2
        ->
    compare performance

======================================================================
25. CATASTROPHIC FORGETTING DEFENSE
======================================================================

Suppose:

    v10
      navigation = excellent
      gathering = excellent
      river = weak

We train heavily on river.

Possible result:

    v11
      river = excellent
      navigation = worse

We therefore rehearse old skills.

Conceptual batch:

    recent difficult examples
    +
    historical important examples
    +
    general examples

The exact sampling ratio becomes an experiment.
